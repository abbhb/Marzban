# Mihomo 级联线路

用于客户端可以连接外部入口、而自建节点不能直接访问的情况：

```text
用户设备 → 外部入口 → 自建落地 → 目标网站
```

## 配置与发布

打开管理端「主机设置」独立页面（`#/hosts`），在左侧搜索并选择目标线路，再进入「级联」分类：

- **通过入口连接，保留原节点名称**：替换原线路，保留现有分组引用和用户选择。
- **保留直连，并新增级联线路**：同时导出原节点和带「级联」后缀的节点。
- **关闭，保持原线路**：恢复原订阅行为，保存时移除该主机的入口配置。

入口可以从共享外部订阅搜索选择，或粘贴一个完整 Clash/Mihomo 节点 YAML。接受节点对象、单项列表，以及只含一个节点的 `proxies` 文档。保留协议和 TLS、Reality、Vision、WS、gRPC、XHTTP 等原始参数，不把入口固定为 VLESS。

编辑区始终显示当前线路的名称、入站和地址。基础信息、连接与 TLS、级联、高级选项分别编辑；切换线路、分类或 XHTTP 方案时保留草稿。「保存全部更改」仅提交修改过的入站，并在保存区列出这些入站。删除线路可以在保存前撤销；离开页面会提示未保存的更改。XHTTP 方案使用其单独的保存按钮。

「检查 YAML 格式」只检查配置结构，不表示网络可达或该协议组合已经通过核心验证。入口必须能够连接落地地址和端口；UDP、特殊传输及不同内核版本需要在实际客户端验证。

套餐继续使用原入站和具体线路授权，无需另给入口分配套餐。落地 UUID/密码仍按订阅用户生成；级联入口只作为依赖加入配置，不加入面板生成的普通节点选择列表。更新原订阅后即可使用。修改主机设置不会重启 Xray。

## 客户端与故障处理

第一版只支持 **Clash Verge / Mihomo（`clash-meta`）完整订阅**。不能把级联导出成一个普通 `vless://` 或 `ss://` 链接，因此用户详情不为级联主机提供单节点分享链接。包含级联线路的其他订阅格式返回 HTTP 422 `cascade_requires_mihomo`，不会静默导出绕过入口的落地节点。

外部订阅刷新时，引用随同一节点的凭据更新。节点消失时保留引用并返回 HTTP 503 `cascade_entry_unavailable`；同一节点重新出现后恢复。源停用、凭据无法解密时同样拒绝生成订阅。被主机引用的源不能直接删除，需要先解除级联引用。

## 升级与存储

包含数据库迁移 `c63e9a0427bd`，部署前需要 `alembic upgrade head`；仓库容器入口已执行这一命令。旧主机默认关闭级联。

粘贴入口复用 `EXTERNAL_SUBSCRIPTION_ENCRYPTION_KEY` 加密存储，密钥要求和备份方式见[外部订阅说明](EXTERNAL-CLASH-SUBSCRIPTIONS.zh-CN.md)。用户订阅必须携带入口凭据，界面隐藏入口不能保密；落地账号仍是用户独立账号。仅 sudo 管理员可以配置和读取入口。

## 验证

后端回归：`python -m unittest tests.test_cascades`。

可选真实内核测试：`MIHOMO_TEST_BINARY=/path/to/mihomo python -m unittest tests.test_cascade_runtime`。该测试在回环地址启动 SOCKS 入口、Shadowsocks 落地和 HTTP 目标，验证两跳成功以及入口断开后不会直连落地，测试转发链路仅使用回环地址。
